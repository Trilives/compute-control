# 开发工具说明

两种模式顶部的“开发工具说明”显示同一份完整工具分层表；申请者另有“申请管理权限”，选择自己的账号并填写事由，由管理员判断帮助安装或授予 sudo 权限。表格与检测清单的唯一来源为 [tool_policy.json](../src/compute_control/tool_policy.json)，不在文档复制第二份。完整操作另见[用户指南](USER_GUIDE.md)及[管理员指南](ADMIN_GUIDE.md)。

- 系统级：共享 Git、C/C++ 编译与构建/调试基础工具、系统 Python、CUDA Toolkit、NVIDIA 驱动，由管理员安装维护。
- 用户级：个人 Python 版本、uv、Pixi、Node.js 等工具，通常在用户目录管理；项目级依赖记录在各项目环境或依赖文件中。
- CMake、Ninja 和部分 ROS 2 依赖可按用途选择系统级或用户/项目级；以表内说明及实际项目需求为准。

首次接入、手动刷新及后台小时探测时，通过既有 SSH 通道执行限时只读版本查询。页面显示状态、版本、可信系统路径；不足 10 分钟的静态版本查询可以复用缓存。缺少工具不会自动阻止申请账号，不自动安装软件。

CUDA Toolkit 检查 `nvcc`，NVIDIA 驱动检查 `nvidia-smi` 驱动查询能否成功；驱动报告的 CUDA 兼容版本不能替代 Toolkit 检测。系统工具使用可信 root 所有且不可被普通用户写入的路径；用户目录和非标准安装可能未检测到，应由管理员核查，不能据此断言整个主机不存在该工具。

系统依赖出现安装、版本或兼容性问题，请联系管理员处理。管理员联系名单在“管理员名单”维护，原联系方式文本可在“申请者与额度”设置，通过申请者顶栏“申请管理权限”右侧的“联系管理员”按钮弹窗显示。所有申请提交后均需主动联系管理员提醒查看，系统不自动发送通知。只读检测不验证每个项目的兼容性，也不改动现有算力任务。
