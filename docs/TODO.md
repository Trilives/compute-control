## 开发约束

- 人类确定目标与验收标准，Agent 主导实现；开工先读[架构](../ARCHITECTURE.md)和本节，再处理下方任务。
- 在现有架构和批准计划内自主推进；变更职责、依赖方向或公共接口先按[架构约定](../ARCHITECTURE.md#104-扩展点与架构变更)确认，同步文档。业务规则与页面、Linux 适配分开。
- 新增依赖记录用途及版本来源，统一管理；配置仅在实际需要时创建，说明用途、允许值、默认值和影响，验证程序读取。秘密遵守[凭据约定](../ARCHITECTURE.md#5-机器添加与凭据)，不提交实际值。
- 真实命令和工具见[验证方法](VERIFICATION.md)；按修改风险验证，区分事实、假设与未知项，不虚构验收结果。
- 任务完成先在 `docs/records/` 保存结果、验收和遗留问题，再从本文件删除该任务；Todo 只保留未完成事项，历史以记录为准。
- 提交前检查差异与暂存内容，只提交当前任务修改，必要时更新 [.gitignore](../.gitignore)；未初始化 Git 时不虚构提交。
- 按[维护计划](MAINTENANCE.md)清理，规则只保留一处；[长度限制](FILE_LENGTH_LIMITS.md)不在文件头重复、不每次编辑检查，清理时可自行调整并说明原因。
- 通用约束变更先与人类讨论。删除其他文件需事先批准及可恢复的 Git 历史，用户明确另行授权时按授权执行；交接记录保留。
