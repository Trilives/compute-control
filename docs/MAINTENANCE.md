# 长期维护与清理

## 触发周期

| 时点 | 项目级检查 | 产出 |
| --- | --- | --- |
| 文档基线（M0） | 全部文件、重复内容、链接、私密边界及长度 | [基线记录](records/2026-11-03-project-baseline.md) |
| M1 本机实现已清理 | 源码、实际命令、配置、任务、指南及长度 | [开发记录](records/2026-11-03-first-implementation.md) |
| 每个实现里程碑完成后、提交或交付前 | 架构与真实代码一致；任务状态、指南、依赖与命令有效；全项目清理 | Todo 验收结果及独立清理记录 |
| 连续开发满一个月而未完成里程碑 | 同上；核查阻塞任务及长期假设 | 月度清理记录；下一次为 2026-12-03，前提是仍在开发 |
| 部署迁移前后 | 配置、凭据供应、地址、日志、备份恢复、权限与防火墙说明 | 部署任务及验证记录；实际环境到位后执行 |

每次任务交付先整理该任务产生的内容；只有到上述周期才要求全项目长度对照与清理。当前仅一位人类与 Agent 协作，执行人为 Agent，目标和验收由人类负责；增加协作者时在相关任务及清理记录注明具体负责人和交接人。

## 项目级清理步骤

1. 读取架构与 Todo 开头的开发约束，确认本次范围；列出全部文件及其用途和入口引用，包括忽略目录中的项目文档。
2. 比较代码、指南、任务与记录，找出重复、过时或没有引用的内容；先核实其用途，任务完成先写结果记录再从 Todo 删除条目，保留有交接价值的历史记录。共享规则只保留一处权威说明，其余改为链接。
3. 按[文件长度规则](FILE_LENGTH_LIMITS.md)测量、精简、按职责拆分或记录理由后调整上限；修复链接和导航。文件删除条件见[开发约束](TODO.md#开发约束)。
4. 执行[验证](VERIFICATION.md)，记录实际结果和未覆盖范围；实现后同时运行当时有效的项目检查，不把文档检查等同于业务验收。
5. 在 `docs/records/` 新建本次记录，关联 Todo，写明发现、处理、未解决项及下次触发点；更新任务状态。普通且依据明确的整理无需逐条说明动机，只有不确定操作或需批准的动作单独给出依据。

## 改进方向与触发条件

| 方向 | 触发条件/里程碑 | 处理边界 |
| --- | --- | --- |
| 从设计到代码 | M1 开始与完成 | 选择实际包管理、锁定版本和目录；补真实启动、测试、格式化命令 |
| Linux 差异与远端安全 | M2 首台测试机接入 | 形成能力矩阵；不足时停止变更，不在既有工作机盲试 |
| 并发额度与中断恢复 | M3 申请流程验收 | 针对竞态与不明远端结果验证，不以页面成功代替远端证据 |
| 归档完整性与恢复 | M4 回收实现 | 在专用测试账号上覆盖异常与恢复，验证后再开放删除 |
| 数据库扩展 | 出现持续写竞争或多控制节点需求 | 依据架构记录瓶颈证据，再讨论数据库迁移 |
| 采集负载 | 机器增长导致排队或长时间过期 | 先量测、错峰及调并发；新增职责或改依赖遵守架构确认规则 |
| 文档规模 | 接近长度限制或内容开始混合职责 | 操作指南、凭据台账按职责拆分；完成任务记入记录后移出 Todo，修复入口 |
| 凭据与部署文档 | 正式部署及每次凭据/地址变更 | 更新私密指南并单独备份；公开记录仅写状态 |

这些是有触发条件的后续改进，不代表当前已经存在对应性能问题或已实现功能。具体任务状态以 [Todo](TODO.md) 为准。
