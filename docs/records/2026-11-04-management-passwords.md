# 网页与机器管理密码修改

后续教程已通用化并压缩为申请者 10 页、管理员 11 页，新增长名单固定添加入口，见[更新记录](2026-11-04-generic-guides-and-sticky-people.md)。

- 用户要求新增管理员修改 Web 管理密码及每台机器密码的能力，并明确机器操作应实际修改 SSH 管理账号的登录密码、同步系统凭据。
- 顶部新增“修改网页管理密码”，每张机器卡片新增“修改机器管理密码”；普通 Linux 账号保留原台账入口，原“更新凭据”继续只检查并保存已另行修改的连接信息。
- 两个表单都验证当前网页管理密码与两次新密码，仅管理员可用，写请求遵守原 CSRF；验证错误不回显秘密，关闭和退出清空输入。

## 行为与边界

- Web 新密码沿用至少 12 字符规则；旧密码验证受登录失败限频约束，事务内再次检查有效会话及旧哈希未变，更新 Argon2 哈希、撤销所有管理员会话，申请者会话保持；使用新密码重新登录。
- 机器新密码至少 3 字符，不能含冒号、换行或 NUL；先检查原 SSH/sudo 连接、固定主机指纹及机器身份，仅修改该机已录入的本地管理账号，不提供任意用户名或命令输入。
- 新的 `machine_password_changes` 表受现有启动模式幂等创建。原机器密文保留，加密候选在 SSH 变更前持久化；新 SSH/sudo 连接验证后才原子替换，候选清空，过程有审计且不记录密码。
- 原先 SSH/sudo 密码相同时一起同步；免密 sudo 或独立的 sudo 认证密码保留原配置，新连接仍须实际通过验证。不结束已有用户进程。
- 有未完成平台任务时拒绝改密；密码结果待核查时阻止重复改密、机器凭据覆盖和新的账号操作。恢复后使用“核查管理密码变更”，只验证和同步，不重放 chpasswd。
- 远端固定动作使用原机器锁，在 root 专属目录按变更 ID 保存无密码回执。明确失败保留原凭据；尚未开始的请求可在锁内记录取消墓碑，防止迟到请求在取消后改密。未知或中断结果保持待核查，不误报成功。
- 程序在远端回执为 started 且新连接仍无法验证时保留待核查，需管理员检查网络及远端状态；不因旧密码仍可用而自动认定失败、覆盖候选或重试。
