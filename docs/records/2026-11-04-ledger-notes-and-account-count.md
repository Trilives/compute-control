# 台账清理、机器备注及同机多账号

人类设置目标和验收标准，Agent 沿用现有账号、页面、数据访问与任务职责实现。本批按用户最新修正交付，前述旧单机限制和联系按钮最右侧安排均被本批规则取代。

## 结果与决策

- 已回收且原 home 已清理、没有 queued/running/waiting_password 任务的账号，管理员或本人可“清理台账”。只记录当前查看身份的隐藏标记，不删除账号/归档/任务/审计；“显示已清理账号”可找回并恢复。不同身份的显示独立，仍有后续清理或执行中的任务不能提前隐藏。
- 接入时录入的 SSH 管理账号默认标为“已登记 · 机器管理员”，不需要申请者归属、不占个人额度，也不生成可自动回收的普通台账；同样用于进程归属显示。其他仅有 sudo 权限的外部账号不会因此被自动冒认。
- 每台机器提供“机器备注”，可见该机的管理员及申请者都能追加共享文字，保存填写人和时间；卡片显示最新摘要，弹窗查看全部。追加不覆盖其他人、内容按纯文本展示，不执行 SSH 命令。
- 管理员入口移到姓名输入窗口右上角，同一按钮在申请者/管理员模式间切换，顶栏不再显示管理员登录入口。
- 联系按钮最终位于申请者顶栏“申请管理权限”右侧，点击弹窗看联系人及旧联系方式；未配置时提示使用公司既有渠道。指南说明所有申请提交后必须主动联系管理员提醒查看，平台不自动发送通知，不把立即创建改成审批。
- 同一人在同机可有多个账号，申请只受个人跨机器总额度限制（默认 3）及用户名重名规则约束；卡片和申请选项仅提示已有数量。重新分配、显式接管同步取消同机数量阻止。数据库移除旧 person_machine 唯一索引，保留普通查找索引及机器用户名唯一性。
- 备注曾在开发热更新阶段返回 404，原因是按钮已生效而运行后端仍是旧版本；已同步重载 Web/worker，真实两台机器备注入口均验证可用。

## 持久化与保护

数据库版本 4 新增 account_ledger_dismissals、machine_notes 及索引；旧版本先生成 `before-v4-from-v<旧版>-*.sqlite3` 一致性备份（600），原账号与历史保留。版本 1/2/3 升级覆盖，升级与重启不重复生成历史点，旧同机唯一索引移除有验证。无新的启动配置或依赖。

台账清理是展示操作，失败回收、原目录待清理、仍占额度和执行中任务均被服务端拒绝；其他申请者不可清理别人的记录。备注只能对可见机器读写，作者取自会话和服务器名单，客户端不能伪造。所有新增写操作沿用会话、CSRF 和审计。
